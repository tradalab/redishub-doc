# Interface & Tabs

RedisHub keeps several connections open side by side. The window has three parts: a narrow **left rail**, a **side panel** next to it, and a **tab area** where each tab shows one view of one connection.

## Left Rail

From top to bottom, the rail holds:

- **Connections** (folder-tree icon) - opens the Connections panel, where you add, organize, connect and filter connections. See [Connection Management](/docs/user-guide/connections).
- **One icon per open connection** - tinted with the connection's color and carrying its state dot (hover for the name and address). A click returns to the tab you last used on that connection and shows its key browser in the side panel. Right-click the icon and choose **Disconnect** to close the connection and all its tabs.
- **Github**, **Report Issues** and **Documentation** at the bottom open the project pages in your browser.
- **Settings** (gear icon, last) opens the [Settings dialog](#settings).

## Tabs

Every tab belongs to one connection and one database. Opening a view that is already open for the same connection and database switches to the existing tab instead of opening a second one.

| Tab            | How to open it                                                     |
|----------------|--------------------------------------------------------------------|
| **General**    | Opens when you connect; also **Views** > **General**                |
| **Key Detail** | Click a key in the key tree or in the Key List                     |
| **Key List**   | **Views** > **Key List**                                            |
| **Console**    | **Views** > **Console**                                             |
| **Pub/Sub**    | **Views** > **Pub/Sub**                                             |
| **Monitor**    | **Views** > **Monitor**                                             |
| **Analysis**   | **Views** > **Analysis**                                            |
| **Slow Query** | **Views** > **Slow Query**                                          |

The **Views** menu is the panel icon in the key browser header. It also holds the **Read-only** switch for the connection (see [Read-only Mode](/docs/user-guide/connections#read-only-mode)).

### Tab indicators
- The tab icon shows the tab type, tinted with the connection's color, with the connection's state dot in its corner (amber connecting, green connected, red unreachable).
- Under the title, a subtitle names the connection and database, for example `Production (DB0)`.
- The active tab is highlighted.

### Working with multiple connections
- Open as many connections as you need (for example Development, Staging and Production); each gets its own icon in the left rail.
- The key browser keeps its filters, key type and expanded folders per connection and database, so switching back finds the view as you left it. This is kept in memory for the session and dropped when the connection closes.

### Managing tabs
- **Close**: click the **x** on a tab.
- Right-click a tab for more actions:
    - **Pin Tab** / **Unpin Tab** - pinned tabs move to the left, and **Close Others** and **Close All** leave them open.
    - **Close Others** - close every other unpinned tab.
    - **Close All** - close every unpinned tab.
- In the desktop app, closing the last tab of a connection disconnects it. In web mode the connection stays open, since other people on the server may be using it.

## Views

### Console
A Redis CLI inside the app, opened from **Views** > **Console**. Each console is tied to one connection and database, and the prompt shows the database (`db0>`).
- **Suggestions**: as you type a command name, matching commands are listed with a short summary; after the command name, matching key names are suggested. Use the arrow keys to move through the list and `Tab` to accept.
- **History**: the Up and Down arrows recall earlier commands run on the same connection and database. History is saved in local storage, so it survives restarts; the most recent 1000 commands are kept, and only commands that succeeded are recorded.
- **Built-in commands**: `CLEAR` clears the screen, `HELP` lists the built-ins, `HISTORY` prints the history for this connection and database.
- **Dangerous commands**: `FLUSHALL`, `FLUSHDB`, `CONFIG`, `SHUTDOWN` and `SCRIPT` are not run the first time. RedisHub asks you to re-type the exact same command, and it runs only if you do so within 30 seconds. Typing a different command cancels the confirmation.
- **Read-only mode** applies here too: write commands are refused on a read-only connection.

### Monitor
The **Monitor** tab streams every command processed by the Redis server in real time.
- **Start Monitor** / **Stop Monitor** controls the stream; **Clear** empties it and **Pause Scroll** stops auto-scrolling.
- **Filtering**: filter the stream by keyword to find specific operations.
- **Caution**: the `MONITOR` command can degrade Redis performance by up to 50% under heavy load. Use with caution in production environments.

### Pub/Sub
The **Pub/Sub** tab lets you subscribe to Redis channels and patterns, and publish messages.
- **Message Streaming**: view incoming messages in real time in the **Message Feed**.
- **Multiple Subscriptions**: subscribe to several channels or patterns (e.g., `events:*`) at once, or use **Subscribe All (\*)**.
- **Publish**: enter a channel and a message, then press **Publish** (or `Ctrl+Enter`).

### Slow Query
Identify performance bottlenecks by inspecting the Redis Slow Log.
- **Execution Time**: see how long each slow command took (**Duration**).
- **Client Info**: see which client sent it (**Client Addr**).

### Analysis
Profile a whole keyspace: how many keys of each type, how their sizes are distributed, how much memory the instance uses, which keys are the largest, and how TTLs are spread.

Three modes, because the cost differs by orders of magnitude:
- **Fast (INFO only)** - the default, and the only one that reads nothing but server counters. It touches no keys at all, so it is safe on a busy production instance. On Redis 8 it also gets the size distribution for free from `INFO keysizes`.
- **Sampled scan** - Fast plus a bounded walk (1k / 10k / 50k / 200k keys) to find the largest keys and the TTL spread. Results are labelled *largest keys in sample*, because a sample cannot prove what the largest key in the whole keyspace is.
- **Full scan** - walks every key. Progress streams while it runs and **Cancel** stops the server-side scan immediately.

Notes on accuracy:
- Total memory comes from `INFO`. Per-key sizes come from `MEMORY USAGE`, which estimates nested elements by sampling, so those are never summed into the instance total.
- Keys of a module type (RedisJSON and friends) are invisible to `INFO keysizes`; the shortfall against `DBSIZE` is shown as **other** with a warning, and a scan counts them properly.
- The last column shows **Idle** or **Freq** depending on `maxmemory-policy`: `OBJECT IDLETIME` and `OBJECT FREQ` exclude each other, so only the one your policy allows is offered.
- On a cluster every master is scanned and the totals are combined.

### General and Key List
The **General** tab shows server information; see [Server Information](/docs/user-guide/connections#server-information). The **Key List** tab shows keys as a sortable table; see [Key Operations](/docs/user-guide/key-operations#key-list).

## Settings

The gear icon at the bottom of the left rail opens the **Settings** dialog. Its **General** panel holds:
- **Theme**: **System**, **Light** or **Dark**.
- **Accent**: recolours buttons and focus rings and tints every surface; status colours never change.
- **Language**: the interface language. The choice is remembered across restarts.
- **Compact Mode**: reduces spacing so more keys and server information fit on screen.
- **Automatic Updates**: **Enable automatic update checks** turns the background check on or off.
- **Check Update**: **Check for updates** looks for a new version now; when one is found, its release notes are shown and **Update now** installs it.

In web mode the two update settings are disabled: the server updates by pulling a new container image.

The **About** panel shows the **Version**, **Platform**, **System language** and **Run mode** (desktop app or web mode).

## Running in the Background

Closing the window does not quit RedisHub - it hides to the system tray and keeps your connections open. This is what you want for an app you check on all day rather than launch and quit.

- **Restore**: double-click the tray icon, or right-click it and choose **Open**.
- **Quit for real**: right-click the tray icon and choose **Quit**.

Available on Windows and Linux. On this path the updater elevates installs on its own, so an update applied from the tray still installs correctly.

## Web Mode

Starting with version 1.9.0, RedisHub can be deployed as a central web application. This is ideal for teams that want a shared Redis management console accessible from any browser without installing native clients on every machine.

For detailed instructions on how to configure and deploy the web version, please refer to the **[Web Mode Deployment Guide](/docs/user-guide/web-mode)**.
