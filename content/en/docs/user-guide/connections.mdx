# Connection Management

RedisHub provides a versatile connection manager designed to handle complex networking and security configurations across Windows, Linux, and macOS.

## Adding a New Connection

1. Open the Connections panel from the folder-tree icon at the top of the left rail, then click the **+** (Plus) icon in the panel header.
2. The **New Connection** dialog is organized into five tabs:
    - **General**: Core configuration (Name, Color, Tags, Mode, Group, Address, Credentials).
    - **Optional**: Read-only mode, performance tuning and NAT traversal.
    - **Proxy**: HTTP/SOCKS5 proxy settings.
    - **TLS/SSL**: Encryption and certificate management.
    - **SSH Tunnel**: Secure access to private networks.
3. Click **Test Connection** to check the settings without saving, then **Save**.

![New Connection Dialog](/assets/en/new-connection.png)

## Connecting and Managing Connections

- **Connect**: double-click a connection in the list. RedisHub connects to the database you used last on it and opens its **General** tab.
- **The row menu**: hover a connection and click its **...** button for **Connect**, **Disconnect**, **Update** (opens the **Update Connection** dialog) and **Delete**. A group's **...** menu has **Update** and **Delete**.
- **Deleting** asks for confirmation. Deleting a connection that is open also disconnects it and closes its tabs.
- An open connection can also be closed from its icon in the left rail (right-click > **Disconnect**); see [Left Rail](/docs/user-guide/interface#left-rail).

## Connection Modes

### Standalone
The standard connection type for a single Redis instance.
- **Network**: Supports both **TCP** (standard) and **Unix Socket** connections.
- **Authentication**: Supports standard Redis password and ACL usernames.

### Cluster
Optimized for high-performance Redis Clusters.
- **Seed Address Import**: Use the "Import from Standalone" link to quickly copy your primary host/port as a seed address.
- **Automatic Discovery**: RedisHub automatically discovers the entire cluster topology from your seed nodes.
- **Slot Mapping**: Intelligent routing ensures commands are sent to the correct master nodes.

### Sentinel
Designed for high-availability setups.
- **Master Group Name**: Specify the name of the monitored master set (e.g., `mymaster`).
- **Sentinel Nodes**: List the addresses of your Sentinel instances for reliable discovery.
- **Dual Credentials**: Support for separate Sentinel-level and Master-level authentication.

## Advanced Networking

SSH tunnels, TLS settings and proxies are saved **profiles** that any number of connections can share. In the **SSH Tunnel**, **TLS/SSL** or **Proxy** tab, turn on **Enable SSH Tunnel**, **Enable TLS/SSL** or **Enable Proxy**, then pick a profile from the dropdown. The **...** button beside the dropdown opens the profile manager (**SSH Configurations**, **TLS/SSL Configurations** or **Proxy Configurations**), where you add, edit and delete profiles.

### SSH Tunnel
Connect to Redis servers located within private VPCs or behind firewalls.
- **Dynamic Routing**: RedisHub uses a dynamic SSH dialer that can reach any discovered node (Sentinel replicas, Cluster shards) through a single SSH tunnel.
- **Authentication**: the profile's **Auth Type** is **Password**, **Keypair** (a PEM private key with an optional passphrase) or **SSH Agent**.
- **Test Connection** in the SSH profile manager checks the tunnel on its own.

![SSH Configuration](/assets/en/ssh-configuration.png)

### Proxy Support (HTTP/SOCKS5)
Route your Redis traffic through intermediate proxy servers.
- **Protocols**: Supports both **HTTP** and **SOCKS5**.
- **Authentication**: Supports proxy-level credentials (User/Pass).

![Proxy Configuration](/assets/en/proxy-configuration.png)

### TLS/SSL & mTLS
Ensure end-to-end encryption for your data.
- **Verification**: Validate server identity using CA certificates.
- **Mutual TLS (mTLS)**: Enhanced security requiring both server and client certificate validation.
- **SNI**: Support for Server Name Indication for virtual hosted targeting.

![TLS Configuration](/assets/en/tls-configuration.png)

## Tuning & Optimization (Optional Tab)

Access these settings under the **Optional** tab for fine-grained control:

### Performance Tuning
- **Execute Timeout**: Maximum time allowed for command execution before timing out.
- **Dial Timeout**: Timeout for establishing the initial network connection.
- **Key Load Size**: Limit the number of keys loaded during scan to ensure UI responsiveness in massive databases.

### Address Mapping (NAT Traversal)
Essential for environments where Redis nodes report internal, unreachable IPs (e.g., Docker or AWS ElastiCache behind NAT).
- **Mapping**: Define rules to translate internal `ip:port` to host-reachable `ip:port`.
- **Syntax**: `internal:port=external:port`, one entry per line.

## Organizing Connections

### Groups, colors and tags
- **Groups** (folder-plus icon in the Connections panel header) gather connections such as *Local*, *Staging* and *Production*. Assign one from the **Group** field of the connection form. Which groups you left open is remembered in this browser.
- **Colors** tint a connection's icon. A connection with no color of its own wears its group's.
- **Tags** are free-form labels in the connection form - press `Enter` or a comma to add one. Use them for whatever the group does not already say: team, region, cluster.

### Filtering
The **Filter** box above the list matches a connection's name, `host:port`, cluster or sentinel addresses, socket path and tags. Groups holding a match open while you type, and close again when you clear the box.

### Connection state
Every opened connection shows a dot - in the list, on its left-rail icon, on its tabs and in its console: amber while connecting, green when connected (hover for the round-trip time), red when the server stops answering. A connection you have not opened shows no dot. A group row counts its connected, connecting and unreachable connections, so an outage stays visible with the group collapsed.

Closing the last tab of a connection disconnects it in the desktop app but not in web mode; see [Managing tabs](/docs/user-guide/interface#managing-tabs).

When a server stops answering, its tabs show a banner with the error and when RedisHub tries again. The next try comes 30 seconds after a failed check, then every 60 seconds while the server stays down; **Reconnect** tries at once.

## Read-only Mode

Connecting to a production or sensitive Redis instance? Enable **Read-only Mode** to explore data with zero risk of accidental modification. When active, RedisHub blocks **every write command** on that connection.

### Enabling it

Read-only mode is **per connection** and persists across restarts. Toggle it from any of:

- The **Read-only** switch in the connection dialog's **Optional** tab.
- The **Read-only** item in the **Views** menu of the key browser header.
- Clicking the amber **READ-ONLY** badge to turn it back off.

### How it works

- **Server-enforced, not just UI.** Writes are rejected at the command layer, covering the key editors, bulk delete, **and** the interactive Console. The blocked-command set is detected from the connected server's own `COMMAND` table (so module writes like `JSON.SET` are caught too), with a curated fallback for servers that restrict `COMMAND`.
- **Graphs still browse.** The Cypher console switches to `GRAPH.RO_QUERY`, so reading a graph keeps working; a query that writes is refused by the server itself.
- **Gated UI.** Add / edit / delete / rename / TTL actions are disabled, with clear feedback when a blocked action is attempted.
- **Clear indicators.** A `READ-ONLY` badge appears in the browser header, and a lock icon marks the connection in the sidebar list.

> **Note:** `PUBLISH` (Pub/Sub messaging) is allowed because it does not modify the keyspace. Administrative commands that change server or data state (e.g. `CONFIG SET`, `FLUSHALL`, `SHUTDOWN`) are blocked.

## Server Information

Once connected, the **General** tab shows the server's information. It opens when you connect, and you can reopen it from **Views** > **General** in the key browser header.

### Summary and sections
- **Summary cards** at the top show **Memory** (used memory), **Keys** in the current database, **Clients** (connected clients) and **Version** with the server's uptime.
- **Sections** on the left list every `INFO` section the server returns (Server, Clients, Memory, Persistence, Stats, Replication, Keyspace and so on). Pick one to see all its fields in a property/value table.

### Refresh Controls
- **Manual Refresh**: click **Refresh** to fetch the latest server info immediately.
- **Auto-Refresh**: off by default. Turn on the switch next to **Auto** to refresh on an interval of 5s, 10s (the default), 30s or 60s.
