# キー操作

RedisHub の直感的なデータブラウザーを使って、データを簡単に閲覧・管理できます。

## キーブラウザー

接続すると、サイドパネルにその接続のキーブラウザーが表示されます。ヘッダーには接続名、状態ドット、現在のデータベース、そして読み取り専用モードがオンのときは **READ-ONLY** バッジが表示されます。右側のアイコンで **Views** メニューを開く、キー一覧を更新する、キーを作成する（**New Key**）ことができます。

### キーの閲覧
- **データベースピッカー**: サーバーが報告するデータベースをキー数付きで一覧表示します（例: `DB3 (15)`）。現在のデータベースについては、読み込み済みのキー数と総数を表示します（例: `DB0 (500/12000)`）。
- **読み込み**: キーは接続の **Key Load Size** ずつ読み込まれます。ツリーの末尾までスクロールすると次の分を読み込みます。データベースピッカーの隣の 2 つのボタンで、次の分を読み込むか、すべてのキーがそろうまで読み込み続けるかを選べます。
- **ツリー**: キーは `:` で区切られたフォルダーにまとめられ、各フォルダーには含まれるキーの数が表示されます。キーをクリックすると **Key Detail** タブで開きます。
- **大規模データ対応**: 50 万件以上のキーを持つデータベース向けに最適化されており、仮想化されたツリーにより高負荷なインスタンスでもスムーズに動作します。

### 絞り込み
**Filter** ボックスは、入力した文字列を含むキー名に一致します（**Contains**、**Ignore case** オン）。隣のスライダーボタンで **Filters** を開くと、さらに次の設定ができます。
- **Key type**: **Any type**、または `string`、`list`、`set`、`zset`、`hash`、`stream`、`rejson-rl`、`graphdata` のいずれか。
- **条件（クローズ）**: 各条件にはモード（**Contains**、**Glob**（例: `user:*`）、**Regex**（例: `^user:\d+$`））と、個別の **Exclude** と **Ignore case** のスイッチがあります。**Add filter** で条件を追加できます。追加の条件はフィルターボックスの下にチップとして表示され、そこから削除できます。
- **Match all** / **Match any**: 包含条件が 2 つ以上あるとき、キーがすべてに一致する必要があるか、いずれかでよいかを選びます。
- **Saved filters**: *Save current filter as…* に名前を入力して **Save** を押すと、現在の条件・一致モード・キー型が保存されます。保存したフィルターをクリックすると適用され、**x** で削除します。保存したフィルターはすべての接続で共通です。

フィルターの実行中は、走査したキー数と一致したキー数が進捗行に表示され、**Stop** で走査を取り消せます。

> **Note:** **Ignore case** を使うと Redis 側での事前絞り込みができなくなるため、キースペース全体が走査されます。

フィルター・キー型・展開したフォルダーは、セッション中は接続とデータベースごとに保持されます。[複数の接続の操作](/ja/docs/user-guide/interface#複数の接続の操作)を参照してください。

### Key List
**Views** > **Key List** を選ぶと、現在のデータベースのキーが名前・型・TTL・サイズの列を持つ表で開きます。列見出しをクリックするとその列で並べ替え、もう一度クリックすると順序が逆になります。型・TTL・サイズは画面に表示されている行について取得されます。表の上にはキーブラウザーと同じフィルターバーがあります。行をクリックするとキーが開き、ゴミ箱アイコンで削除します。

## Key Detail

**Key Detail** タブは、共通のヘッダーの下にキーの値を表示します。
- **型バッジ**と**キー名**。名前を編集して隣の保存アイコンをクリックするとキーをリネームします。**Copy** ボタンで名前をコピーします。
- **TTL**: 残りの有効期間、または **No expiry** が表示されます。クリックすると **Update TTL** が開き、秒数を入力します。`-1` で有効期限を解除します。
- **Refresh** でキーを再読み込みし、**Delete** で確認のうえ削除します。
- ヘッダーの下の帯には、値の **Length**、メモリ使用量（**Memory**、`MEMORY USAGE`）、内部エンコーディング（**Encoding**、`OBJECT ENCODING`）が表示されます。

## データの編集

RedisHub は主要な Redis データ型をすべてサポートしています。

### 文字列（String）
値を 1 つのテキストエディタで表示・編集し、**Save** を押します。

### JSON（RedisJSON）
RedisJSON ドキュメント（`ReJSON-RL`）を直接閲覧・編集できます。開くと整形表示され、編集して **Save** を押すとドキュメント全体が書き戻されます。不正な JSON はサーバーに送る前に拒否され、キーは文字列に変換されず JSON ドキュメントのまま保たれます。
- **作成**: 新規キーのダイアログで型に **JSON** を選択します。
- **絞り込み**: キー型フィルターで **rejson-rl** を選ぶと JSON ドキュメントのみが一覧されます。
- **必要条件**: RedisJSON モジュールを備えた Redis サーバー。Redis 8 は本体に同梱、Redis 7 では `redis-stack` が必要です。

- **値がたまたま JSON である通常の文字列とは異なります。そちらは `string` キーのままで、文字列エディタでテキストとして開きます。**

### グラフ（RedisGraph / FalkorDB）
`graphdata` キーは値エディタではなく **Cypher コンソール** で開きます。グラフには表示すべき単一の値が存在しないためです。クエリを入力して **Run**（または `Ctrl+Enter`）を押すと、結果を 2 通りの方法で確認できます。
- **Graph**: 対話的なノードリンク表示。ドラッグで移動、スクロールで拡大縮小、ノードにホバーまたはクリックすると隣接ノードが強調され、プロパティが表示されます。結果が大きい場合は 300 ノードで打ち切られ、その旨がバッジで示されます。
- **Table**: サーバーが返した行と列をそのまま表示します。ノードとリレーションは JSON として描画されます。

ヘッダーにはグラフのノード数とリレーション数、含まれるラベルとリレーションタイプが表示され、いずれかをクリックすると対応するクエリがエディタに入力されます。
- **作成**: 新規キーのダイアログで型に **GRAPH** を選び、グラフを作成する Cypher を入力します。
- **絞り込み**: キー型フィルターで **graphdata** を選ぶとグラフのみが一覧されます。
- **必要条件**: グラフモジュール。RedisGraph は 2023 年にサポートを終了しており、[FalkorDB](https://www.falkordb.com/) が保守されているフォークで、同じコマンドに対応しています。

### ハッシュ（Hash）
フィールドと値のペアを表形式で管理します。個々のフィールドの追加、編集、削除ができます。

### リスト（List）
リストの要素を順序どおりに表示し、個々の要素を編集・削除できます。**Insert Row** で新しい要素をリストの先頭に追加します（`LPUSH`）。

### セット（Set）
セットのユニークなメンバーを管理します。

### ソート済みセット（ZSet）
メンバーと、それに関連付けられたスコアを管理します。

### ストリーム（Stream）
ストリームのエントリを、その ID とフィールドと値のペアとともに閲覧できます。

## 共通の操作
- **キーの削除**: ツリーのキーにホバーして **...** > **Delete** を選ぶか、Key Detail ヘッダーの **Delete** を使います。
- **一括削除**: フォルダーにホバーして **...** > **Delete** を選ぶと、そのプレフィックス配下のすべてのキーを削除できます。一致するキーがプレビューに一覧表示されます（検索したり、**Load More** / **Load All** でさらに表示したりできます）。その後、次のいずれかを選びます。
    - **Delete Preview (n)** は、プレビュー一覧にあるキーだけを削除します。
    - **Delete Everything** は再度確認（**Delete Everything?**）したうえで、プレビューに表示されていないキーも含め、そのプレフィックスを持つすべてのキーを削除します。

  キーは `SCAN` で見つけて 1000 件ずつ削除するため、サーバーをブロックしません。進捗は通知に表示されます。
- **キーのリネーム**: Key Detail ヘッダーで名前を編集して保存します。
- **TTL の設定**: Key Detail ヘッダーの TTL をクリックします。

読み取り専用モードでは、削除・リネーム・TTL の操作は無効になります。
