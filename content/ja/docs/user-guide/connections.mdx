# 接続管理

RedisHub は、Windows、Linux、macOS にまたがる複雑なネットワークおよびセキュリティ設定に対応できるよう設計された、多用途の接続マネージャーを提供します。

## 新しい接続の追加

1. 左レール上部のフォルダーツリーアイコンから接続パネルを開き、パネルのヘッダーにある **+**（プラス）アイコンをクリックします。
2. **New Connection** ダイアログは、5 つのタブに整理されています。
    - **General**: 基本設定（名前、色、タグ、モード、グループ、アドレス、認証情報）。
    - **Optional**: 読み取り専用モード、パフォーマンスチューニング、NAT トラバーサル。
    - **Proxy**: HTTP/SOCKS5 プロキシ設定。
    - **TLS/SSL**: 暗号化と証明書の管理。
    - **SSH Tunnel**: プライベートネットワークへの安全なアクセス。
3. **Test Connection** で保存せずに設定を確認し、**Save** を押します。

![New Connection Dialog](/assets/en/new-connection.png)

## 接続と接続の管理

- **接続**: 一覧の接続をダブルクリックします。RedisHub はその接続で最後に使ったデータベースに接続し、**General** タブを開きます。
- **行のメニュー**: 接続にホバーして **...** ボタンをクリックすると、**Connect**、**Disconnect**、**Update**（**Update Connection** ダイアログを開く）、**Delete** があります。グループの **...** メニューには **Update** と **Delete** があります。
- **削除**には確認が求められます。開いている接続を削除すると、切断されてそのタブも閉じます。
- 開いている接続は、左レールのアイコンからも閉じられます（右クリック > **Disconnect**）。[左レール](/ja/docs/user-guide/interface#左レール)を参照してください。

## 接続モード

### Standalone
単一の Redis インスタンスに接続するための標準的な接続タイプです。
- **Network**: **TCP**（標準）と **Unix Socket** の両方の接続をサポートします。
- **Authentication**: 標準的な Redis パスワードと ACL ユーザー名をサポートします。

### Cluster
高性能な Redis Cluster 向けに最適化されています。
- **Seed Address Import**: 「Import from Standalone」リンクを使用すると、プライマリのホスト/ポートをシードアドレスとして素早くコピーできます。
- **Automatic Discovery**: RedisHub はシードノードからクラスター全体のトポロジーを自動的に検出します。
- **Slot Mapping**: インテリジェントなルーティングにより、コマンドが正しいマスターノードに送信されることを保証します。

### Sentinel
高可用性構成向けに設計されています。
- **Master Group Name**: 監視対象のマスターセットの名前（例: `mymaster`）を指定します。
- **Sentinel Nodes**: 確実な検出のために、Sentinel インスタンスのアドレスを一覧で指定します。
- **Dual Credentials**: Sentinel レベルとマスターレベルで別々の認証をサポートします。

## 高度なネットワーキング

SSH トンネル、TLS 設定、プロキシは、複数の接続で共有できる保存済みの**プロファイル**です。**SSH Tunnel**、**TLS/SSL**、**Proxy** の各タブで **Enable SSH Tunnel**、**Enable TLS/SSL**、**Enable Proxy** をオンにし、ドロップダウンからプロファイルを選びます。ドロップダウンの隣の **...** ボタンでプロファイル管理画面（**SSH Configurations**、**TLS/SSL Configurations**、**Proxy Configurations**）が開き、プロファイルの追加・編集・削除ができます。

### SSH Tunnel
プライベート VPC 内やファイアウォールの背後にある Redis サーバーに接続します。
- **Dynamic Routing**: RedisHub は動的な SSH ダイヤラーを使用し、単一の SSH トンネルを通じて検出済みの任意のノード（Sentinel レプリカ、Cluster シャード）に到達できます。
- **Authentication**: プロファイルの **Auth Type** は **Password**、**Keypair**（PEM 形式の秘密鍵と任意のパスフレーズ）、**SSH Agent** のいずれかです。
- SSH プロファイル管理画面の **Test Connection** で、トンネル単体を確認できます。

![SSH Configuration](/assets/en/ssh-configuration.png)

### Proxy Support (HTTP/SOCKS5)
Redis のトラフィックを中継プロキシサーバー経由でルーティングします。
- **Protocols**: **HTTP** と **SOCKS5** の両方をサポートします。
- **Authentication**: プロキシレベルの認証情報（ユーザー/パスワード）をサポートします。

![Proxy Configuration](/assets/en/proxy-configuration.png)

### TLS/SSL & mTLS
データのエンドツーエンドの暗号化を確保します。
- **Verification**: CA 証明書を使用してサーバーの ID を検証します。
- **Mutual TLS (mTLS)**: サーバーとクライアント両方の証明書検証を必要とする、強化されたセキュリティです。
- **SNI**: バーチャルホストされたターゲットを指定するための Server Name Indication をサポートします。

![TLS Configuration](/assets/en/tls-configuration.png)

## チューニングと最適化（Optional タブ）

きめ細かな制御を行うには、**Optional** タブで以下の設定にアクセスします。

### パフォーマンスチューニング
- **Execute Timeout**: コマンド実行がタイムアウトするまでに許容される最大時間。
- **Dial Timeout**: 最初のネットワーク接続を確立する際のタイムアウト。
- **Key Load Size**: スキャン中に読み込まれるキーの数を制限し、大規模なデータベースでも UI の応答性を確保します。

### アドレスマッピング（NAT トラバーサル）
Redis ノードが内部の到達不能な IP を報告する環境（例: NAT の背後にある Docker や AWS ElastiCache）で不可欠です。
- **Mapping**: 内部の `ip:port` をホストから到達可能な `ip:port` に変換するルールを定義します。
- **Syntax**: `internal:port=external:port`、1 行につき 1 エントリ。

## 接続の整理

### グループ・色・タグ
- **グループ**（接続パネルのヘッダーにあるフォルダー追加アイコン）で *Local*・*Staging*・*Production* などに接続をまとめます。接続フォームの **Group** で割り当てます。開いていたグループはこのブラウザーに記憶されます。
- **色** は接続のアイコンを色付けします。色を持たない接続はグループの色を使います。
- **タグ** は接続フォームで自由に付けられるラベルです。`Enter` またはカンマで追加します。チーム・リージョン・クラスターなど、グループで表せない軸に使います。

### フィルター
一覧上部の **Filter** は、接続名・`host:port`・Cluster/Sentinel のアドレス・ソケットパス・タグに一致します。入力中は一致を含むグループが開き、入力を消すと元に戻ります。

### 接続状態
開いた接続には、一覧、左レールのアイコン、タブ、コンソールにドットが付きます。接続中は黄、接続済みは緑（ホバーで往復時間を表示）、サーバーが応答しなくなると赤です。開いていない接続にはドットが付きません。グループの行には接続済み・接続中・到達不能の数が表示されるため、グループを閉じていても障害が見えます。

接続の最後のタブを閉じると、デスクトップ版では切断されますが Web モードでは切断されません。[タブの管理](/ja/docs/user-guide/interface#タブの管理)を参照してください。

サーバーが応答しなくなると、そのタブにエラーと次の再試行までの時間を示すバナーが出ます。失敗した確認の 30 秒後に再試行し、停止が続く間は 60 秒ごとに再試行します。**Reconnect** で即座に再試行します。

## 読み取り専用モード

本番環境や機密性の高い Redis インスタンスに接続していますか？ **読み取り専用モード**を有効にすると、誤って変更してしまうリスクをゼロにしてデータを探索できます。有効な間、RedisHub はその接続における**すべての書き込みコマンド**をブロックします。

### 有効化する

読み取り専用モードは**接続ごと**に設定され、再起動後も維持されます。以下のいずれかから切り替えられます。

- 接続ダイアログの **Optional** タブにある **Read-only** スイッチ。
- キーブラウザーのヘッダーにある **Views** メニューの **Read-only** 項目。
- 黄色い **READ-ONLY** バッジをクリックして再びオフにする。

### 動作の仕組み

- **UI だけでなくサーバー側で強制されます。** 書き込みはコマンド層で拒否され、キーエディター、一括削除、**さらに**対話型コンソールまでを対象とします。ブロック対象のコマンドセットは、接続先サーバー自身の `COMMAND` テーブルから検出されるため（`JSON.SET` のようなモジュールの書き込みも捕捉されます）、`COMMAND` を制限しているサーバー向けには厳選されたフォールバックも用意されています。
- **グラフの閲覧は可能です。** Cypher コンソールは `GRAPH.RO_QUERY` に切り替わるため、グラフの読み取りは引き続き行えます。書き込みを伴うクエリはサーバー自身が拒否します。
- **UI のゲート制御。** 追加 / 編集 / 削除 / 名前変更 / TTL の操作は無効化され、ブロックされた操作が試みられた際には明確なフィードバックが表示されます。
- **明確なインジケーター。** ブラウザーのヘッダーに `READ-ONLY` バッジが表示され、サイドバーの一覧ではロックアイコンが接続を示します。

> **Note:** `PUBLISH`（Pub/Sub メッセージング）はキースペースを変更しないため許可されます。サーバーやデータの状態を変更する管理コマンド（例: `CONFIG SET`、`FLUSHALL`、`SHUTDOWN`）はブロックされます。

## サーバー情報

接続すると、**General** タブにサーバーの情報が表示されます。このタブは接続時に開き、キーブラウザーのヘッダーの **Views** > **General** から開き直せます。

### サマリーとセクション
- 上部の**サマリーカード**には、**Memory**（使用メモリ）、現在のデータベースの **Keys**、**Clients**（接続中のクライアント数）、サーバーの稼働時間付きの **Version** が表示されます。
- 左側の **Sections** には、サーバーが返すすべての `INFO` セクション（Server、Clients、Memory、Persistence、Stats、Replication、Keyspace など）が並びます。選ぶと、そのすべてのフィールドがプロパティと値の表で表示されます。

### 更新の制御
- **Manual Refresh**: **Refresh** をクリックすると、最新のサーバー情報を即座に取得します。
- **Auto-Refresh**: 既定ではオフです。**Auto** の隣のスイッチをオンにすると、5s、10s（既定）、30s、60s の間隔で自動更新します。
