# インターフェースとタブ

RedisHub では複数の接続を並べて開いておけます。ウィンドウは 3 つの部分で構成されます。細い**左レール**、その隣の**サイドパネル**、そして各タブが 1 つの接続の 1 つのビューを表示する**タブ領域**です。

## 左レール

左レールには上から順に次のものが並びます。

- **Connections**（フォルダーツリーのアイコン）: 接続パネルを開きます。ここで接続の追加・整理・接続・絞り込みを行います。[接続管理](/ja/docs/user-guide/connections)を参照してください。
- **開いている接続ごとのアイコン**: 接続の色で色付けされ、状態ドットが付きます（ホバーで名前とアドレスを表示）。クリックすると、その接続で最後に使ったタブに戻り、サイドパネルにその接続のキーブラウザーを表示します。アイコンを右クリックして **Disconnect** を選ぶと、接続とそのすべてのタブを閉じます。
- 下部の **Github**、**Report Issues**、**Documentation** は、プロジェクトのページをブラウザーで開きます。
- 最後の **Settings**（歯車アイコン）は[設定ダイアログ](#設定)を開きます。

## タブ

各タブは 1 つの接続と 1 つのデータベースに属します。同じ接続・同じデータベースですでに開いているビューを開こうとすると、2 つ目を開かずに既存のタブに切り替わります。

| タブ           | 開き方                                                             |
|----------------|--------------------------------------------------------------------|
| **General**    | 接続時に開きます。**Views** > **General** からも開けます            |
| **Key Detail** | キーツリーまたは Key List でキーをクリック                         |
| **Key List**   | **Views** > **Key List**                                            |
| **Console**    | **Views** > **Console**                                             |
| **Pub/Sub**    | **Views** > **Pub/Sub**                                             |
| **Monitor**    | **Views** > **Monitor**                                             |
| **Analysis**   | **Views** > **Analysis**                                            |
| **Slow Query** | **Views** > **Slow Query**                                          |

**Views** メニューは、キーブラウザーのヘッダーにあるパネルアイコンです。接続の **Read-only** スイッチもここにあります（[読み取り専用モード](/ja/docs/user-guide/connections#読み取り専用モード)を参照）。

### タブのインジケーター
- タブのアイコンはタブの種類を示し、接続の色で色付けされ、角に接続の状態ドット（接続中は黄、接続済みは緑、到達不能は赤）が付きます。
- タイトルの下のサブタイトルに、接続名とデータベースが表示されます（例: `Production (DB0)`）。
- アクティブなタブはハイライトされます。

### 複数の接続の操作
- 必要なだけ接続を開けます（例: 開発、ステージング、本番）。それぞれに左レールのアイコンが付きます。
- キーブラウザーは、フィルター・キー型・展開したフォルダーを接続とデータベースごとに保持するため、戻ったときに離れたときの表示のままです。これはセッション中メモリに保持され、接続を閉じると破棄されます。

### タブの管理
- **閉じる**: タブの **x** をクリックします。
- タブを右クリックすると、さらに操作できます。
    - **Pin Tab** / **Unpin Tab**: ピン留めしたタブは左側に移動し、**Close Others** と **Close All** でも閉じられません。
    - **Close Others**: ほかのピン留めされていないタブをすべて閉じます。
    - **Close All**: ピン留めされていないタブをすべて閉じます。
- デスクトップ版では、接続の最後のタブを閉じると切断されます。Web モードでは、サーバーの他の利用者が使っている可能性があるため接続は維持されます。

## ビュー

### Console
アプリ内の Redis CLI で、**Views** > **Console** から開きます。各コンソールは 1 つの接続とデータベースに紐付き、プロンプトにデータベースが表示されます（`db0>`）。
- **候補表示**: コマンド名を入力すると、一致するコマンドが短い説明付きで一覧表示されます。コマンド名の後では、一致するキー名が候補に出ます。矢印キーで一覧を移動し、`Tab` で確定します。
- **履歴**: 上下の矢印キーで、同じ接続・同じデータベースで実行した過去のコマンドを呼び出せます。履歴はローカルストレージに保存されるため再起動後も残ります。保持されるのは直近の 1000 件で、成功したコマンドだけが記録されます。
- **組み込みコマンド**: `CLEAR` は画面をクリア、`HELP` は組み込みコマンドを一覧表示、`HISTORY` はこの接続・データベースの履歴を表示します。
- **危険なコマンド**: `FLUSHALL`、`FLUSHDB`、`CONFIG`、`SHUTDOWN`、`SCRIPT` は 1 回目には実行されません。RedisHub がまったく同じコマンドの再入力を求め、30 秒以内に再入力した場合にのみ実行されます。別のコマンドを入力すると確認は取り消されます。
- **読み取り専用モード**はここにも適用され、読み取り専用の接続では書き込みコマンドが拒否されます。

### Monitor
**Monitor** タブは、Redis サーバーが処理するすべてのコマンドをリアルタイムでストリーミングします。
- **Start Monitor** / **Stop Monitor** でストリームを制御します。**Clear** で表示を消去し、**Pause Scroll** で自動スクロールを止めます。
- **Filtering**: キーワードでストリームを絞り込み、特定の操作を見つけられます。
- **Caution**: `MONITOR` コマンドは、高負荷時に Redis のパフォーマンスを最大 50% 低下させる可能性があります。本番環境では注意して使用してください。

### Pub/Sub
**Pub/Sub** タブでは、Redis のチャンネルとパターンのサブスクライブと、メッセージのパブリッシュができます。
- **Message Streaming**: 受信メッセージを **Message Feed** にリアルタイムで表示します。
- **Multiple Subscriptions**: 複数のチャンネルやパターン（例: `events:*`）を同時にサブスクライブできます。**Subscribe All (\*)** も使えます。
- **Publish**: チャンネルとメッセージを入力し、**Publish**（または `Ctrl+Enter`）を押します。

### Slow Query
Redis のスローログを調べて、パフォーマンスのボトルネックを特定します。
- **Execution Time**: 遅いコマンドそれぞれの実行時間（**Duration**）を確認できます。
- **Client Info**: どのクライアントが送ったか（**Client Addr**）を確認できます。

### Analysis
キースペース全体をプロファイルします。型ごとのキー数、サイズの分布、インスタンスのメモリ使用量、最大のキー、TTL の分布を確認できます。

コストが桁違いに異なるため、モードは 3 つあります。
- **Fast (INFO only)** - 既定。サーバーのカウンターだけを読み、キーには一切触れないため、稼働中の本番インスタンスでも安全です。Redis 8 では `INFO keysizes` からサイズ分布も無償で取得します。
- **Sampled scan** - Fast に加えて、上限付き（1k / 10k / 50k / 200k キー）で走査し、最大のキーと TTL の分布を調べます。結果は *largest keys in sample* と表示されます。サンプルからキースペース全体の最大キーは断定できないためです。
- **Full scan** - すべてのキーを走査します。実行中は進捗がストリーミングされ、**Cancel** でサーバー側の走査を即座に停止できます。

精度についての注意:
- 総メモリは `INFO` 由来です。キーごとのサイズは `MEMORY USAGE` の推定値（入れ子要素はサンプリング）であり、総メモリには合算されません。
- モジュール型（RedisJSON など）のキーは `INFO keysizes` からは見えません。`DBSIZE` との差は **other** として警告付きで表示され、走査すれば正しく計上されます。
- 最終列は `maxmemory-policy` に応じて **Idle** または **Freq** を表示します。`OBJECT IDLETIME` と `OBJECT FREQ` は排他のため、ポリシーが許す方だけが提供されます。
- クラスターでは全マスターを走査し、合計して表示します。

### General と Key List
**General** タブはサーバー情報を表示します。[サーバー情報](/ja/docs/user-guide/connections#サーバー情報)を参照してください。**Key List** タブはキーを並べ替え可能な表で表示します。[キー操作](/ja/docs/user-guide/key-operations#key-list)を参照してください。

## 設定

左レール下部の歯車アイコンで **Settings** ダイアログが開きます。**General** パネルには次の項目があります。
- **Theme**: **System**、**Light**、**Dark**。
- **Accent**: ボタンとフォーカスリングの色を変え、すべての面に色味を加えます。状態を示す色は変わりません。
- **Language**: インターフェースの言語。選択は再起動後も保持されます。
- **Compact Mode**: 余白を減らし、より多くのキーやサーバー情報を画面に表示します。
- **Automatic Updates**: **Enable automatic update checks** でバックグラウンドの更新確認をオン・オフします。
- **Check Update**: **Check for updates** で新しいバージョンを今すぐ確認します。見つかった場合はリリースノートが表示され、**Update now** でインストールします。

Web モードでは、この 2 つの更新設定は無効です。サーバーは新しいコンテナイメージを取得して更新します。

**About** パネルには **Version**、**Platform**、**System language**、**Run mode**（デスクトップアプリか Web モードか）が表示されます。

## バックグラウンド実行

ウィンドウを閉じても RedisHub は終了せず、システムトレイに収納されて接続を維持します。起動と終了を繰り返すのではなく、一日中確認するようなアプリに適した挙動です。

- **復帰**: トレイアイコンをダブルクリック、または右クリックして **Open** を選択します。
- **完全に終了**: トレイアイコンを右クリックして **Quit** を選択します。

Windows と Linux で利用できます。この経路では更新プログラムが自身で権限昇格するため、トレイから適用した更新も正しくインストールされます。

## Web モード

バージョン 1.9.0 以降、RedisHub は中央集約型の Web アプリケーションとしてデプロイできます。これは、各マシンにネイティブクライアントをインストールすることなく、あらゆるブラウザーからアクセスできる共有 Redis 管理コンソールを求めるチームに最適です。

Web バージョンの設定とデプロイの詳細な手順については、**[Web モード デプロイガイド](/ja/docs/user-guide/web-mode)**を参照してください。
