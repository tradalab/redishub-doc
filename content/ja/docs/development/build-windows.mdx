# Windows 向けのビルド

Windows 用の成果物（`.msi`）は `scorix` CLI を使ってネイティブにビルドされます。Docker は不要です。MSI
のステップには WiX Toolset が必要です。

## 前提条件

- **Go 1.27**、**Node.js 24**、**pnpm 11.22.0** - [はじめに](/ja/docs/development/setup) を参照。
- **WiX Toolset v7** - EULA に同意し、UI/Util 拡張機能をインストールしておきます（CI と同じ手順です）:
  ```bash
  dotnet tool install --global wix --version 7.0.0
  wix eula accept wix7
  wix extension add -g WixToolset.UI.wixext/7.0.0
  wix extension add -g WixToolset.Util.wixext/7.0.0
  ```
- **scorix CLI** - `@latest` ではなく `go.mod` にピン留めされたバージョンをインストールしてください。
  [はじめに](/ja/docs/development/setup) を参照。

## ビルドの手順

プロジェクトのルートから実行します。

```bash
make package          # scorix package - builds the binary + wraps it into an MSI
```

または、OS/アーキテクチャを明示的に指定するために `scorix` を直接呼び出します（CI ではこれを実行しています）。

```bash
scorix package -d . --os windows --arch amd64
```

`scorix package` は `wix build` を自身で呼び出すため、実行前に EULA への同意と拡張機能のインストールを済ませておく必要があります。
リリースは意図的に署名なしで配布されます。`scorix.yaml` で署名が無効化されている（`sign.windows.enabled: false`）ため、
MSI は署名されず、初回実行時に SmartScreen が警告を表示します。

## 出力先

- `artifacts/RedisHub-<version>-windows-amd64.msi`（バージョンは `scorix.yaml` の `app.version` に追従します）

> [!NOTE]
> CI は、ネイティブの `windows-2022` ランナー上で同じ `scorix package` ステップを実行します。`.github/workflows/release.yml`
> が `tradalab/scorix` の再利用可能な `scorix-release.yml` を呼び出し、`v*` タグがプッシュされると `scorix.yaml` の
> すべてのターゲットを 1 つのマトリックスとしてビルドします。
