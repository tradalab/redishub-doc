# 新しい IPC コマンドの追加

RedisHub は、**Protobuf コントラクトから生成される** **プロセス間通信 (IPC)** レイヤーによって、Go バックエンドと Next.js フロントエンドを橋渡しします。コマンドは `service:method` のパターンに従います (例: `client:connect`。これは proto の `rpc` `client.Connect` から生成されます)。

コマンドルーターを手作業で記述することは**ありません**。`internal/handler/handler.go` と `internal/types/types.go` は生成されるファイルであり、それぞれに `// Code generated by scorix. DO NOT EDIT.` ヘッダーが付いています。コマンドを追加するには、proto を編集し、再生成してから、ロジックのスタブを実装します。

---

## ステップ 1: `proto/app.proto` でコントラクトを宣言する

該当する `service` に、リクエスト/レスポンスメッセージと `rpc` を追加します。fire-and-forget な呼び出しには `returns (Empty)` を、リクエスト/レスポンス型の呼び出しにはレスポンスメッセージを、サーバーストリーミングコマンド (`monitor:Start` や `console:Exec` など) には `returns (stream …)` を使用します。

```proto
message MyActionReq {
  string connection_id  = 1;
  int32  database_index = 2;
  string custom_param   = 3;
}

message MyActionRes {
  string result = 1;
}

service client {
  // ... existing rpcs
  rpc MyAction(MyActionReq) returns (MyActionRes);
}
```

---

## ステップ 2: ハンドラー、型、モデルを再生成する

```bash
make generate
```

これは `scorix generate proto` と `scorix generate model` を実行します。proto からは、Go ハンドラー (`internal/handler/handler.go`)、Go の型 (`internal/types`)、**そして**型付きのフロントエンドクライアント (`shell/api/index.ts`) が再生成されます。`etc/schema.sql` からは sqlx モデル (`internal/model`) が再生成されます。これで新しいコマンドが両側に登録されます。

---

## ステップ 3: ビジネスロジックを実装する

`internal/logic/<service>/<action>_logic.go` を作成します。生成されたハンドラーは、`(ctx, svcCtx)` を使ってロジックを構築し、デコードされたリクエストとともにメソッドを呼び出します。

```go
package client

import (
	"context"

	"github.com/tradalab/rdms/internal/svc"
	"github.com/tradalab/rdms/internal/types"
)

type MyActionLogic struct {
	ctx    context.Context
	svcCtx *svc.ServiceContext
}

func NewMyActionLogic(ctx context.Context, svcCtx *svc.ServiceContext) *MyActionLogic {
	return &MyActionLogic{ctx: ctx, svcCtx: svcCtx}
}

func (l *MyActionLogic) MyAction(req *types.MyActionReq) (any, error) {
	// 1. Resolve the Redis client via l.svcCtx.RedisManager
	// 2. Perform the operation
	// 3. Return a serializable result (or *types.MyActionRes) and error
	return &types.MyActionRes{Result: "ok"}, nil
}
```

> [!NOTE]
> **サーバーストリーミング** の rpc の場合、生成されたハンドラーは `app.Sink[T]` を接続します。`MyAction(req *types.MyActionReq, out app.Sink[types.MyEvent]) error` を実装し、`out.Send(...)` でフレームをプッシュします。実際の例については `internal/logic/monitor/start_logic.go` を参照してください。

---

## ステップ 4: フロントエンドから呼び出す

`shell/api/index.ts` にある生成済みの型付きクライアントを使用します。proto の `rpc` `client.MyAction` は `client.myAction(params)` として公開されます (ワイヤー名は `client:my-action`)。

```typescript
import { client } from "@/api";

const res = await client.myAction({
  connection_id: "123",
  database_index: 0,
  custom_param: "hello",
});
```

ストリーミングコマンドは代わりに async-iterable を返します。例えば `monitor.start(params)` はフレームを yield します (`for await (const frame of monitor.start(...))`)。内部では、すべての処理が自動注入される `window.scorix` ブリッジ (`scorix.invoke` / `scorix.serverStream`) を経由します。

> [!TIP]
> proto を唯一の信頼できる情報源として保ちましょう。フィールドを変更する場合は `proto/app.proto` を編集して `make generate` を再実行します。生成された `handler.go` / `types.go` / `shell/api/index.ts` を手作業で編集してはいけません。
